# 후속 개발

## 공용 MCP와 다중 사용자

1. Streamable HTTP stateless와 로컬 사용자별 매핑·동시 제한·종료 수명은 구현했다. 실제 사용자 A/B의 Backend 권한 검증과 공용 인증 전환을 별도로 완료한다.
2. MCP OAuth 보호 리소스 및 인가 서버 연계, audience·scope·토큰 만료/철회 검증을 구현한다. 기존 Backend 세션 토큰과 OAuth 토큰을 구분한다.
3. 현재 로컬 세션 매핑을 표준 사용자 동의·Backend 위임 토큰 교환으로 교체한다. 공용 관리자 토큰이나 비밀번호 자동 로그인을 사용하지 않는다.
4. 로컬 제한·격리 검증을 공용 TLS·프록시·중앙 감사·다중 프로세스 운영으로 확장한다.

## 변경 신청과 운영 통제

1. ACL·Flink ACL·컬럼 DDL 미리보기는 v0.2.0에서 구현했다. 신청·반영·실행은 별도 범위로 유지한다.
2. Backend가 멱등성 키와 요청 상태 재조회를 보장하게 하여 LLM·네트워크 재시도에 의한 중복 신청을 방지한다.
3. 기존 승인·반영·감사 체계를 유지한다. MCP가 승인자 분리, 정책, Kafka 변경 로직을 복제하거나 직접 실행하지 않는다.
4. 사용자 확인은 실제 대상 클러스터, 변경 전후 값, 영향 범위와 정책 결과가 준비된 시점에 받는다.

## 내부 LLM 채팅 서비스

사용자 인증과 위임을 MCP 세션에 연결하고 도구 결과의 부분 실패·신선도·잘림을 사용자에게 표시한다. 이벤트 설명 같은 외부 문자열을 지시와 분리한다. 변경 신청은 조회 도구와 다른 허용 정책을 적용하며 신청 ID와 승인/반영 상태를 기존 Backend에서 추적한다. 이 저장소에는 채팅 UI나 LLM 호출을 추가하지 않았다.

## Backend 계약 개선 후보

- 이벤트 조치 이력 `/events/{id}/actions`에 서버 측 limit/cursor와 최신순 정렬을 추가한다. 현재는 전체 이력을 반환하므로 새 이벤트 상세 도구의 `include:["actions"]`는 `unsupported`다.
- 토픽 상세에 동기화 시각과 클러스터별 카탈로그 메타를 제공하고, 설정의 직접 지정/상속 출처를 명시한다. 멤버 API에는 그룹 존재 여부·상태와 원본 관측 시각을 추가한다.
- 자산 영향 요약에 클러스터 ID·수집 시각·수집 실패·대상 존재 여부를 제공하고 서버 노드 수 제한을 추가한다. 현재 그래프와 영향 요약은 각각 자산을 수집한다.
- 신청 조회에 안전한 실패 코드·사유와 재시도 가능 여부, 제한된 상태 이력 계약을 추가한다. 현재 자유 형식 의견·실패 원문은 MCP가 공개하지 않으며 레거시 빈 clusterId는 기본 클러스터로 해석하지 않는다.

- 토픽·Consumer Group 목록에 초기 동기화 실패와 마지막 성공/실패 상태를 명시하여 `syncedAt=null`의 빈 목록이 데이터 없음과 구별되도록 한다.
- 전체 반환 API에 서버 측 필터·정렬·페이지 또는 cursor 계약을 추가한다. MCP 출력 제한으로 REST 전송량까지 줄일 수는 없다.
- 모든 실시간 조회의 관측 시각과 데이터 모드를 일관되게 제공하고 진단 오류의 민감정보 제거 계약을 강화한다.
- 파티션 건강 응답에 관측 성공 파티션 수를 명시한다. 현재 실패 카운터는 토픽 단위와 파티션 단위가 섞여 있어 MCP가 일부 관측 성공을 확정할 수 있는 조건이 제한된다.
- Consumer Group 경로 파라미터의 percent decoding 계약을 명시하고 `/` 등 인코딩된 문자가 포함된 그룹명도 실제 대상과 일치하는지 라우터 통합 테스트로 검증한다. 현재 MCP는 경로를 인코딩하며 대상이 불일치한 응답을 거부한다.
- 운영 환경에서는 본인 테스트 계정으로 인증 만료·클러스터 권한·사설 CA·대용량 목록을 별도 연동 검증한다. mock 검증을 실제 Backend 연동 성공으로 간주하지 않는다.

## v0.2.0에서 확인한 Backend 선행 과제

보류한 12개 도구와 재개 조건은 [보안](security-tools.md#백엔드-보완-전-보류), [이벤트](event-tools.md#backend-제약으로-보류한-도구), [데이터 연계](data-tools.md#backend-제약으로-보류한-연계-도구)에 기록했다. 전역 API에 클러스터 인자를 추가하는 것만으로 권한 검사·객체 소속이 보완되었다고 판단하지 않는다. 기존 get_event_detail의 Issue 확장도 멤버 상한과 N+1 해소 전까지 호출하지 않는다.

저장소/스냅샷 실패·실측/mock·관측 시각을 일관되게 반환해야 현재 partial 결과를 확정 관측으로 다룰 수 있다. 샘플 본문 전달 확대는 별도의 데이터 공개 정책과 Backend의 출처/부분 실패 계약이 필요하며 현재 허용 범위는 위치 메타데이터뿐이다.
